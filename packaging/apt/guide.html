The creature and the code

Meet the app.

Klicky adds mechanical keyboard sounds to an ordinary keyboard on Linux, macOS and Windows 11 x64. It includes ten sound packs, volume control, overlapping playback and native desktop integration. It runs locally as your user, without an account or subscription.

The creature beneath the keys is our fictional mascot. The application is a focused Rust utility, not an AI assistant, game or virtual pet.

System Current distribution Controls
Linux Debian/Arch packages; source installer CLI, systemd; optional Omarchy toggle
macOS Source installer Menu toggle, CLI, launchd
Windows 11 x64 Unsigned installer and portable ZIP Native tray and CLI

Releases and the source changelog cover downloads and changes. Project-owned Homebrew and Scoop packages are available. Chocolatey and Cargo installation are not published.

Choose a doorway

Installation.

Use your desktop's normal terminal, as your user. Linux package setup asks for sudo when needed; the app remains unprivileged. Inspect the Unix or PowerShell helper first if you prefer.

Linux packages/source · macOS source + menu bar · Windows installer/portable

Linux.

Ubuntu 24.04+ / compatible Debian amd64, or Arch / Omarchy x86_64: 

curl -fsSL https://klicky.muneer320.tech/install.sh | bash

The helper verifies the pinned APT key or Arch release checksum, installs the package and sounds, and enables/starts the systemd user service. Use a terminal with curl; APT setup installs GnuPG if missing. Debian packages need glibc 2.39+, libasound2t64, systemd and udev.

Compatible Omarchy QML shells get the toggle automatically. To skip it: 

curl -fsSL https://klicky.muneer320.tech/install.sh | bash -s -- --no-omarchy-toggle
Use APT directly

After configuring the signed repository:

sudo apt install klicky
systemctl --user enable --now klicky.service

For key inspection and manual setup, use the APT guide. Confirm exactly one primary key: DBB6 7AE4 78D2 FFCE C663 7B55 9899 E554 D358 0D8F.

Download and install a package

Choose only your distribution's commands. The automatic helper additionally handles key/checksum verification. 

# Ubuntu / compatible Debian
curl -fL --retry 2 -o klicky.deb https://klicky.muneer320.tech/pool/main/k/klicky/klicky_0.5.0-1_amd64.deb
sudo apt install ./klicky.deb
systemctl --user enable --now klicky.service

# Arch / Omarchy
curl -fL --retry 2 -o klicky.pkg.tar.zst https://github.com/Muneer320/klicky/releases/download/v0.5.0/klicky-0.5.0-1-x86_64.pkg.tar.zst
sudo pacman -U ./klicky.pkg.tar.zst
systemctl --user enable --now klicky.service

Build from source

For other distributions/architectures, older systems or development: 

curl -fsSL https://klicky.muneer320.tech/install.sh | bash -s -- --source

This prepares missing Rust 1.87, compiler and ALSA development dependencies on supported APT/pacman/dnf systems, then builds and starts Klicky using systemd/udev. Existing checkout: 

git clone https://github.com/Muneer320/klicky.git
cd klicky
./scripts/install-linux.sh

Checkouts need Rust 1.87+, Git, a compiler, pkg-config and ALSA headers (libasound2-dev on Ubuntu/Debian; alsa-lib-devel on Fedora). For non-systemd setup or source-to-package migration, see advanced installation.

macOS.

curl -fsSL https://klicky.muneer320.tech/install.sh | bash

Prepares missing Rust and Apple tools, builds the app, installs the menu helper and enables login startup. Approve Apple's tools dialog if shown. First setup can take several minutes; this is a source installation. For Homebrew-managed setup, use the tap below.

Grant Accessibility to ~/.local/bin/klicky in System Settings → Privacy & Security → Accessibility. Setup opens the pane, shows the installed file and retries while you approve it.

Skip the helper:

curl -fsSL https://klicky.muneer320.tech/install.sh | bash -s -- --no-menu

From a checkout with Rust 1.87+ and Apple build tools:

./scripts/install-macos.sh
./scripts/install-macos-menu-bar.sh

The menu toggles the daemon; change packs/volume through the CLI. Quitting the helper closes the menu, not the daemon.

Homebrew on macOS.

On Apple Silicon, with Homebrew and Apple Command Line Tools installed:

brew install muneer320/tap/klicky && brew services start muneer320/tap/klicky && klicky service enable

The tap builds the app, sounds and menu helper from source. Grant Accessibility to the actual binary shown by brew info klicky, then run klicky service start. To omit the menu, leave out brew services start muneer320/tap/klicky.

Intel Macs use the one-line source installer. Klicky still supports Intel; Homebrew has ended its supported Intel coverage. Remove a previous source installation without purge before switching. Keep one installation and one menu helper.

Update or remove Homebrew Klicky

Update:

klicky service stop && brew update && brew upgrade muneer320/tap/klicky && brew services restart muneer320/tap/klicky && klicky service start

If you do not use the menu, omit brew services restart muneer320/tap/klicky from that line.

Remove both login registrations and the package:

klicky service disable && brew services stop muneer320/tap/klicky && brew uninstall muneer320/tap/klicky

Run the full removal line before uninstalling; plain brew uninstall cannot clean the independently managed daemon registration. Settings/custom packs stay in ~/Library/Application Support/klicky. Delete that folder afterward only if you want to erase them too. Tap documentation.

Scoop on Windows.

With Scoop installed, run in normal PowerShell:

scoop bucket add klicky https://github.com/Muneer320/scoop-bucket
scoop install klicky/klicky
klicky service start

The complete portable package includes all sounds and a Start shortcut. Enable login startup with klicky service enable. Remove an existing installer copy before switching; settings can carry over.

Update or remove Scoop Klicky

Scoop checks running processes before updating, so stop first:

klicky service stop
scoop update
scoop update klicky
klicky service start

Remove with scoop uninstall klicky. Its hook stops only the owned app and removes only its login shortcut. Shared settings/custom packs remain in %LOCALAPPDATA%\Klicky, including with Scoop's --purge. Delete that folder only after removing every Klicky copy if you also want to erase your data. Bucket documentation.

Windows.

Windows 11 x64 desktop. Run in PowerShell:

irm https://klicky.muneer320.tech/install.ps1 | iex

Downloads a published installer, verifies its SHA-256 and opens per-user setup. Choose login startup in the wizard. Rust, Visual Studio and elevation are not needed. The helper starts the installed app afterward, respecting a paused launch.

Download the setup EXE or portable ZIP. For portable use, extract everything into a stable folder and open klicky-desktop.exe. Keep both executables, sounds and notices together.

Windows downloads are unsigned. Windows 10, ARM64 and x86 are not initial targets. Security help · Windows controls and recovery guide.

Your first few clicks.

On Linux/macOS, check the app, choose a sound and set the volume: 

klicky list
klicky status
klicky switch cherrymx-blue-pbt
klicky volume 0.5

If the shell cannot find a source installation, use ~/.local/bin/klicky. Linux packages install /usr/bin/klicky. Windows has tray controls and this installed CLI: 

& "$env:LOCALAPPDATA\Programs\Klicky\klicky.exe" status

Select the intended speakers/headphones and type briefly. On Windows, Resume if paused. The macOS menu toggles sounds; Linux uses its service controls.

CLI reference.

Common commands below work on Unix and Windows. Windows uses the installed path above, or .\klicky.exe from a portable folder; it is not added to PATH.

Command Purpose
list List bundled/system and user packs.
switch NAME Choose a pack; save for next start if stopped.
volume LEVEL Set a finite value from 0.0 (mute) to 1.0.
status Show settings and responsive live state.
start Run in the foreground; stop a managed instance first.
stop Stop and confirm process exit.
service start / stop Change this session; keep the login-startup choice.
service enable / disable Start now and at login / stop now and disable startup.
service status Show login startup and app state.
--help / --version Inspect the CLI and build.

Windows additions

pause, resume, retry-audio and read-only diagnostics. service start --paused affects a newly launched instance. Foreground start also takes --paused, --seconds N (1–3600) and aggregate --benchmark diagnostics.

Linux/macOS benchmark mode

start --benchmark prints mapped key names and internal timing. Use only for controlled tests, never while typing sensitive information. Windows-only pause/seconds/diagnostics commands do not exist on Unix.

A successful live pack/volume command confirms the change was loaded, saved and applied. If a response fails or times out, check status and logs before retrying. Full CLI reference →

Configuration.

Two fields in config.toml:

sound_pack = "eg-oreo"
volume = 0.8
System User settings and sounds
Linux ~/.config/klicky / $XDG_CONFIG_HOME/klicky
macOS ~/Library/Application Support/klicky
Windows %LOCALAPPDATA%\Klicky

Use controls for live changes; edit configuration while stopped. Custom packs go in the neighboring sounds folder and override system/bundled names.

KLICKY_SYSTEM_SOUNDS_DIR overrides the secondary pack root; Windows requires an absolute path. KLICKY_SKIP_UDEV=1 skips the Linux source installer's device rule when access is managed elsewhere. These are advanced environment options, not config fields. Configuration reference →

A sound of your own.

Ten bundled packs: Cherry MX Black, Blue, Brown and Red with PBT/ABS variants, EG Oreo and EG Crystal Purple. Listen in the sound room.

A custom pack is a directory containing sound.ogg and config.json. The JSON maps keys to [start_ms, duration_ms]: 

{
  "defines": {
    "KeyA": [0, 120],
    "Space": [235, 180],
    "Return": [415, 150]
  },
  "name": "My Pack"
}

Copy it into your sounds folder, then select it:

# Linux example; use the corresponding macOS/Windows path above.
mkdir -p ~/.config/klicky/sounds
cp -R my-pack ~/.config/klicky/sounds/
klicky switch my-pack

A malformed or undecodable pack leaves the current one active. Include common keys, avoid clipping and redistribute only recordings you have permission to use. Format and supported key names →

Under the keycaps.

One resident application serves the user session. Native input feeds the platform runtime; shared preparation decodes OGG with Symphonia, creates per-key PCM slices and applies capped normalization when loading a pack.

  1. Native input

    Linux evdev / macOS event taps / Windows passive Raw Input.

  2. Cached PCM

    Select prepared samples and apply the user's volume.

  3. Persistent mixer

    Overlap key sounds through the platform renderer.

Platform Runtime / control Audio
Linux/macOS Unix daemon, channels, Unix socket IPC; systemd/launchd. Rodio MixerDeviceSink.
Windows Event-driven coordinator, bounded input/control work, pack worker, native tray and current-logon-protected named pipes. Rodio mixer, supervised Windows CPAL renderer and bounded voices.

Windows gates capture outside the verified active/unlocked desktop and discards obsolete input across transitions. Its adapters preserve the separate Unix implementation. Module map, concurrency and lifecycle →

Local sounds. Sensitive permissions.

Normal operation does not store typed text, log key names, record microphone audio or make network requests. Installation helpers download files; the running app needs no cloud service.

Global keyboard access is sensitive. macOS requires Accessibility; Linux uses a keyboard-only udev rule; Windows receives passive Raw Input without elevation. Grant access only to software you trust. Do not make input devices world-readable.

Unix benchmarks print mapped key names; Windows diagnostics use aggregate counters. The website has no analytics, account or global keyboard listener. Its small script copies commands and prevents overlapping previews. Security model and private reporting →

Responsive by design.

Decoding, slicing and normalization happen at pack load. Keypress playback reuses cached PCM and an existing output stream instead of opening a device or decoding OGG for every press.

This does not guarantee a particular physical latency, CPU load or memory footprint on every system. Device buffering, drivers, Bluetooth and load matter. Internal dispatch timings and requested buffer sizes do not measure physical keypress-to-audible delay.

Compare speakers or wired output when diagnosing an out-of-sync feeling. Read the measurement guide →

When the clicks go quiet.

No sound or intermittent missing sounds

Check state, pack, volume and selected output. In Windows, Resume and try Retry audio. Compare diagnostics before/after a problem from the same process; they contain aggregate counters. Random missing ordinary key sounds are worth reporting even if restarting helps. 

& "$env:LOCALAPPDATA\Programs\Klicky\klicky.exe" status
& "$env:LOCALAPPDATA\Programs\Klicky\klicky.exe" diagnostics
Linux input or startup problems 
klicky status
systemctl --user status klicky.service
journalctl --user -u klicky.service -n 50 --no-pager

Confirm the keyboard-only udev rule; log out/in after permission changes. Newly attached keyboards may need systemctl --user restart klicky.service. Check command -v klicky if a source binary shadows a package. Wayland uses the same backend.

macOS input or missing menu

Grant Accessibility to the installed ~/.local/bin/klicky, not a development copy. Then stop/start its service. Inspect daemon and helper separately: 

~/.local/bin/klicky service status
launchctl print "gui/$(id -u)/dev.klicky.daemon"
launchctl print "gui/$(id -u)/dev.klicky.menu"

Reinstall a missing helper from the checkout. Quitting its menu does not stop the daemon.

Windows starts late after sign-in

Windows can defer Startup-folder apps while busy. Open Klicky from Start to use it sooner, then Resume if paused. Check Start with Windows in the tray and Settings → Apps → Startup. Klicky does not change the system-wide delay.

Windows Security blocks setup or the app

Stop setup and keep protection enabled. Do not add an exclusion or restore a quarantined file just to finish. Note the build/detection name, keep full logs private and use the private reporting route. A suspected false positive needs confirmation. Antivirus detections and unsigned-app reputation warnings are different issues.

A pack or volume change did not apply

Check status, custom-pack precedence and daemon logs. Successful live commands confirm loading, saving and activation; a timeout needs investigation before retrying. Use controls instead of editing active configuration. A rejected pack must not replace a working one.

More troubleshooting · Report a bug. Include OS, build, output and reproduction steps; you need not share what you typed.

Good questions.

Can I use any keyboard?

Yes; a mechanical keyboard is optional. Firmware-only Fn actions and some vendor keys may not emit supported keyboard events.

Can I use Bluetooth?

Yes, through the selected output. Bluetooth transport can add delay that smaller app buffers cannot remove; compare speakers or wired output.

Does it run in the background?

Yes. Linux/macOS setup enables login startup; Windows offers opt-in startup. Native controls and service commands can stop sounds or disable startup.

Is Klicky free?

The app is MIT-licensed and needs no subscription/account. Third-party fonts and dependencies retain their licenses and notices.

Is the mascot an app feature?

The character is our fictional visual identity. Klicky is a sound utility, with no AI conversations, virtual-pet obligations, typing rewards or streaks.

Keep your resident up to date.

Settings and custom sounds are preserved. Stop packaged Linux processes before replacing the binary, including copies in other signed-in sessions: 

# APT repository
systemctl --user stop klicky.service
sudo apt update && sudo apt install --only-upgrade klicky
systemctl --user start klicky.service

For Arch, install the newer release package instead of the APT command. For source installs, rerun the download installer or update the checkout and rerun the platform scripts, including the macOS helper. Check Accessibility again if replacement stops macOS input.

Windows: run the newer installer. It verifies shutdown and preserves the running/pause choice. Disable owned startup and quit before replacing/moving a portable copy. Keep recovery material after a failed update. Recovery details →

Until the next click.

Removal stops the app, disables owned login startup and removes installed controls. Settings and custom sounds stay by default. Purge explicitly deletes them.

Linux / macOS

curl -fsSL https://klicky.muneer320.tech/uninstall.sh | bash

Also delete personal settings/sounds:

curl -fsSL https://klicky.muneer320.tech/uninstall.sh | bash -s -- --purge

Linux handles the package/source copy, service, device rule, APT source/key and supported Omarchy control. Other signed-in users must stop packaged copies first. macOS unloads daemon/helper and removes their binaries, LaunchAgents and menu images. Rust and Apple tools remain; Accessibility permission can be removed manually.

Windows installer setup

irm https://klicky.muneer320.tech/uninstall.ps1 | iex

Complete the native wizard. Also remove settings, custom sounds and installer data: 

& ([scriptblock]::Create((irm https://klicky.muneer320.tech/uninstall.ps1))) -Purge

Use -WhatIf instead of -Purge to preview. Failed/cancelled native removal keeps personal data. Settings → Apps → Installed apps also has the uninstaller.

Windows portable copy

Disable that bundle's login startup in its tray, choose Quit and delete only its extracted folder. The helper does not search drives or delete arbitrary portable/development folders. After closing all copies, its purge command can remove shared settings. Complete removal guide →
