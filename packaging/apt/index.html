Nobody knows quite what Klicky is, or how it found its way into the keyboard. We do know one thing: it absolutely loves sounds.

A single click perks its ears up. A steady rhythm gets its little feet moving. A long typing session? Best day ever.

Behind the character is a focused little app. Klicky adds mechanical keyboard sounds to your own keyboard, with native input capture, prepared audio and straightforward controls. You choose the sound. Klicky supplies the personality.

A little magic. Careful engineering.

Small job.
Thoughtful internals.

The character is imaginary. The software is a native Rust utility built around one job: playing a prepared sound when a key goes down.

Explore the architecture →
Prepared audio

Decode OGG recordings and prepare key slices when a pack loads. Reuse cached PCM and a persistent mixer while typing.

Native input

Linux evdev, macOS event taps and Windows passive Raw Input, with controls that fit each desktop.

Local by default

Normal operation stores no typed text and makes no network requests. No account, telemetry or cloud sound service.

  1. 01 · A physical keypress

    A native adapter maps the keyboard event to a sound-pack key name.

  2. 02 · A prepared slice

    The platform's runtime selects cached PCM and applies your volume.

  3. 03 · Persistent playback

    The mixer overlaps sounds through the OS audio output. No OGG decoding on each press.

Linux/macOS use the Unix daemon and Rodio output; Windows has its own event-driven coordinator and CPAL renderer. Output hardware matters: requested buffer sizes and internal timings are not physical audible latency. Performance, without the hand-waving →

A few good questions

Before you move in.

The field guide has setup steps, commands, configuration, troubleshooting and complete removal instructions.

Do I need a mechanical keyboard?

No. Klicky adds the sound in software. Your ordinary laptop or desktop keyboard works too.

Does Klicky record what I type?

Normal operation does not store typed text, log key names or make network requests. It reads global keyboard events locally to select sounds, so its input permission is sensitive. Unix benchmark mode does print mapped key names; use it only for controlled tests. Read the privacy details.

Will this feel responsive with headphones?

Klicky uses prepared audio and a persistent output stream. Your device still affects timing: Bluetooth can add noticeable transport delay. Compare speakers or wired headphones if it feels out of sync. No universal latency figure is promised.

Can I add sounds or change the volume?

Yes. Use the Windows tray or the CLI to choose packs and volume. Custom packs contain one OGG recording and a JSON timing map. User packs override bundled packs with the same name. Pack format and locations.

Does Linux work on Wayland?

Yes. The evdev backend reads keyboard devices below Wayland and X11. The installer sets up a keyboard-only udev rule; Klicky itself runs as your user.

How do I update or remove everything?

Use your package manager or rerun the appropriate installer to update. The one-command uninstallers stop the app and remove installed desktop controls. Settings and custom sounds stay unless you explicitly choose purge. Portable Windows folders are removed explicitly.

Can I help build Klicky?

Very much so. Useful bug reports, sound-pack work, documentation and focused code changes are welcome. Start with the contribution guide. The app is MIT-licensed; included fonts retain their own open license.
